### 基础设施与部署

- [INFRA-001] **Windows + Docker Desktop + WSL2 存在容器网络隔离问题** | EverMemOS 部署实践 | 高 | 2026-03-04 | ✅ 已验证
  - 证据：即使端口映射 (0.0.0.0:27017)，Windows 主机仍无法连接容器
  - 证据：Docker Desktop 使用 WSL2 后端，容器网络与主机网络隔离
  - 解决方案：将应用也容器化，连接到同一 Docker 网络
  - 含义：Windows 上部署多容器应用时，应全部容器化而非混合部署

- [INFRA-002] **工作区迁移至非系统盘可缓解磁盘压力** | 内部实践 | 高 | 2026-03-04 | ✅ 已验证
  - 证据：C 盘使用率 94.9% (剩余 11GB)，迁移 82.67MB 工作区至 D 盘
  - 证据：openclaw.json 中 agents.defaults.workspace 配置支持自定义路径
  - 含义：大文件/数据库应存放于非系统盘，避免 C 盘空间告急

- [INFRA-003] **Windows PowerShell 脚本需 ASCII 化输出避免编码错误** | arxiv-daily/medium-watcher 修复 | 高 | 2026-03-04 | ✅ 已验证
  - 证据：emoji 字符在 GBK 终端无法编码 (UnicodeEncodeError)
  - 证据：中文文件名导致 Git 提交失败
  - 解决方案：emoji→ASCII 文本 ([OK]/[ERROR])，文件名 ASCII 安全化
  - 含义：Windows 跨平台脚本应使用 ASCII 兼容输出

- 方案 A: 端口映射 + 主机访问 (简单但不可行)
- 方案 B: 禁用 WSL2 使用 Hyper-V 后端 (影响其他容器)
- 方案 C: 全容器化部署 (推荐)  
**选择理由:** 全容器化是 Windows + Docker Desktop 的标准解决方案，避免网络隔离问题  
**实现:**
- 6 个基础设施容器 (MongoDB, Redis, Elasticsearch, Milvus, MinIO, etcd)
- 应用容器 evermemos-app 连接同一 memsys-network
- .env 配置修改：localhost → Docker 服务名  
**结果追踪:** 2026-03-11 验证部署稳定性
