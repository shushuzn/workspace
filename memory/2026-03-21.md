## Reflections & Logic

### Common Errors & Prevention

| Error | Cause | Prevention |
|-------|-------|------------|
| `'{' was never closed` | Chinese quotes in print() | Use `<name>` instead of `"name"` |
| `index out of range` | sys.argv parsed wrong by shell | Use `_arg(idx, default)` method |
| File truncated | write_file too large | Use templates, validate after write |
| Git push blocked | Secrets detected | Only commit tool code, not dialog/credentials |

### Best Practices for Tool Creation

1. **Generate, Don't Write**: Use `safe_coder_001.py --gen cli <name>` instead of writing files manually
2. **Validate Immediately**: Run `tool_validator_001.py --check <file>` after creation
3. **Check Integrity**: Run `file_integrity_001.py <file>` for truncation
4. **Use Snippets**: Assemble from `snippet_001.py --get <name>` for common patterns

### Code Patterns (Safe)

```python
# Safe argv parsing
def _arg(self, idx, default=None):
    return sys.argv[idx] if len(sys.argv) > idx else default

# Safe JSON
json.loads(Path(f).read_text(encoding="utf-8", errors="replace"))

# Windows Unicode fix
if sys.platform == 'win32':
    import io
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')

# Safe dict access (CRITICAL for stock analysis tools)
data.get('key', default_value)
data.get('reports', [{}])[0].get('field', 'N/A')
```

## Reflection: Idle Game Development

### User Feedback Patterns

1. **"添加自动保持"** → Added auto-save + status display
2. **"浅色模式"** → CSS variables + theme toggle
3. **"修复无法启动"** → Simplified start.bat to direct open
4. **"优化游戏"** → Added achievements, stats, animations
5. **"增加标签页"** → Tab navigation between sections
6. **"继续优化"** → Upgrades, more buildings, click mechanic
7. **"没有点击项"** → Made gold area clickable with visual feedback
8. **"点击没有获取"** → Fixed event binding to use specific ID

### Best Practices for Game Development

1. **Event binding**: Always use specific ID selectors, not class selectors for single elements
2. **Null checks**: Always check `if (element)` before adding listeners
3. **Debug logging**: Add console.log during development to trace execution
4. **Progressive disclosure**: Start simple, add features incrementally based on feedback
5. **Visual feedback**: Every action should have visible response (animations, numbers)
