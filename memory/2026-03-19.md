**原因:** Windows 控制台默认 GBK 编码，Python 输出 UTF-8 中文时乱码

**解决方案:**
```batch

set PYTHONUTF8=1
set PYTHONIOENCODING=utf-8
chcp 65001
```

## 📜 工具调用规则（强制性）

### 核心原则（写入 tools_registry.json）

1. **唯一数据源原则** - 所有工具只允许有一份唯一定义
2. **引用优先原则** - 工作流只引用 tool_id，禁止硬编码
3. **实时生效原则** - 工具修改后引用自动同步生效
4. **禁止重写工具原则** - 所有工具脚本禁止被其他脚本重写或修改
5. **统一调用原则** - 所有工具只能通过 tool_executor.py 调用，禁止直接调用工具脚本

### 强制规则

| 规则 | 内容 | 违规示例 | 合规示例 |
|------|------|----------|----------|
| tool_calling | 所有工具必须通过 tool_executor.py 调用 | `subprocess.run(['py', 'tool.py'])` | `subprocess.run(['tool_executor.py', 'tool_id'])` |
| tool_modification | 禁止重写或修改工具脚本 | `open('tool.py', 'w').write()` | 通过 tools_registry.json 配置调整 |
| tool_registration | 新工具必须注册到 tools_registry.json | 创建未注册的工具 | 使用 register_tools.py 注册 |

### 审查机制

**文件:** `30-scripts-tools/check_tool_rules.py`

**检查项:**
1. 直接调用工具脚本（违规）
2. 重写/修改工具脚本（违规）
3. 未注册工具（违规）

**执行:** `py 30-scripts-tools/check_tool_rules.py`

**结果:** ✅ 0 违规（652 个文件检查通过）

## 📝 经验教训

1. **编码问题必须系统级解决** - 在脚本中添加编码设置不可靠，应使用批处理文件设置环境变量
2. **工具调用必须统一入口** - 通过 tool_executor 确保步骤追踪、日志记录、强制检查统一生效
3. **规则必须自动化审查** - 文档规则容易被忽视，自动化审查脚本确保规则执行
4. **工具注册必须及时** - 新工具创建后立即注册，避免审查违规
