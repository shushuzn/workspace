## 📝 核心问题

**研究问题:** 企业级 Agentic AI 如何在私有遥测数据上实现确定性落地 (Deterministic Grounding)

**三大挑战:**
1. **模型上下文限制:** LLM 上下文窗口有限，无法处理海量遥测数据
2. **本地语义概念:** 企业自定义指标/术语，LLM 无法理解
3. **接口演变:** 遥测接口频繁变更，导致工具漂移 (Tool Drift)

---

## 🏗️ 解决方案：REGAL 架构

### 核心设计理念

> **确定性计算作为一等公民** + **LLM 在有界动作空间上操作**

```
┌─────────────────────────────────────────────────────────────┐
│                    LLM Agent                                │
│         (在有界动作空间上操作，不直接接触原始数据)             │
└─────────────────────┬───────────────────────────────────────┘
                      │ MCP 工具调用
                      ▼
┌─────────────────────────────────────────────────────────────┐
│              Registry-Driven Compilation Layer              │
│         (从声明式指标定义合成 MCP 工具，接口即代码)            │
└─────────────────────┬───────────────────────────────────────┘
                      │ 编译/验证
                      ▼
┌─────────────────────────────────────────────────────────────┐
│              Medallion ELT Pipeline                         │
│    Bronze → Silver → Gold (可回放、语义压缩的工件)           │
└─────────────────────┬───────────────────────────────────────┘
                      │ 确定性计算
                      ▼
┌─────────────────────────────────────────────────────────────┐
│              Enterprise Telemetry Sources                   │
│  Git/CI-CD/Issue Tracker/Observability (原始数据流)          │
└─────────────────────────────────────────────────────────────┘
```

### 两大核心组件

#### 1. Medallion ELT Pipeline

| 层级 | 说明 | 特点 |
|------|------|------|
| **Bronze** | 原始遥测数据 | 完整但冗余 |
| **Silver** | 清洗/标准化 | 结构化、去噪 |
| **Gold** | 语义压缩工件 | 可回放、LLM 友好 |

**关键创新:** Gold 层是"语义压缩"的结果，而非简单聚合

#### 2. Registry-Driven Compilation

- **输入:** 声明式指标定义 (YAML/JSON)
- **输出:** MCP 工具 (可执行代码)
- **机制:** 接口即代码 (Interface-as-Code)

**解决的问题:**
- ✅ 工具漂移 (Tool Drift) → Registry 保证一致性
- ✅ 语义对齐 → 编译时验证
- ✅ 治理策略 → 嵌入语义边界

## 💡 核心洞察

### 1. 架构方法 vs 算法方法
- **本文定位:** 不提出新学习算法
- **核心贡献:** 将确定性计算和语义编译提升为设计原语
- **关键思想:** 架构问题 > 规模问题

### 2. 确定性 vs 概率性
| 层面 | 处理方式 | 技术 |
|------|----------|------|
| 遥测计算 | **确定性** | ELT Pipeline |
| LLM 推理 | **概率性** | 有界动作空间 |
| 工具调用 | **确定性** | Registry 编译 |

**设计原则:** 用确定性约束概率性，而非对抗

### 3. MCP 的深度应用
- MCP 不仅是工具协议
- MCP 是**语义边界**的实现机制
- Registry 编译确保 MCP 工具与底层数据对齐
