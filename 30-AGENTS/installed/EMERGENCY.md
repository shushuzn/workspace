# 🚨 应急处理指南

**创建日期:** 2026-03-27

---

## 紧急程度分级

| 级别 | 定义 | 响应时间 | 示例 |
|------|------|----------|------|
| 🔴 **P0** | 服务不可用 | 即时 | 进程崩溃、数据丢失 |
| 🟠 **P1** | 核心功能受损 | 15 分钟 | 登录失败、支付异常 |
| 🟡 **P2** | 非核心功能异常 | 1 小时 | 通知失败、缓存问题 |
| 🟢 **P3** | 轻微问题 | 24 小时 | UI 显示、边缘 case |

---

## 常见问题与处理

### 1. Agent 无响应

**症状:** 消息无回复

**检查项:**
```bash
# 1. 检查 Agent 进程
ps aux | grep copaw

# 2. 检查日志
tail -n 100 logs/error.log

# 3. 检查资源
df -h
free -m
```

**处理:**
1. 重启 Agent
2. 清理缓存
3. 检查网络连接

---

### 2. 文件系统问题

**症状:** 无法读写文件

**检查项:**
```bash
# 1. 检查磁盘空间
df -h

# 2. 检查权限
ls -la /path/to/file

# 3. 检查文件锁
lsof /path/to/file
```

**处理:**
1. 清理不需要的文件
2. 修复权限
3. 重启相关进程

---

### 3. API 限流/失败

**症状:** 外部服务调用失败

**检查项:**
- 检查 API Key 是否有效
- 检查配额是否用完
- 检查网络连接

**处理:**
1. 等待限流恢复
2. 降级到备用服务
3. 增加重试间隔

---

### 4. 安全事件

**症状:** 发现异常访问/数据泄露

**立即行动:**
```
1. 记录证据 (日志、截图)
2. 停止受影响的服务
3. 通知管理员
4. 不要自行处理
```

**报告格式:**
```
🚨 安全事件报告

时间: {timestamp}
类型: {incident_type}
影响: {impact}
证据: {evidence}
日志: {log_location}
```

---

### 5. 数据损坏

**症状:** 文件损坏、数据库异常

**立即行动:**
1. 停止写入操作
2. 不要重启服务
3. 尝试从备份恢复
4. 记录损坏情况

**恢复流程:**
```bash
# 列出可用备份
backup.bat list

# 选择备份点
backup.bat restore {date}

# 验证完整性
verify-integrity.bat
```

## 恢复步骤清单

### 完整恢复

```
□ 1. 评估损失
□ 2. 停止服务
□ 3. 备份当前状态
□ 4. 恢复数据
□ 5. 验证完整性
□ 6. 重启服务
□ 7. 监控稳定性
□ 8. 通知相关方
□ 9. 写事后报告
```

### 快速恢复

```
□ 1. 重启服务
□ 2. 验证基本功能
□ 3. 监控 5 分钟
□ 4. 如正常，继续监控
□ 5. 如异常，完整恢复
```
