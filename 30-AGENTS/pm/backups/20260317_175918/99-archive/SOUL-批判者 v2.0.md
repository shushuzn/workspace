## 📋 批判标准 (v2.1 实战版 - Day 2 经验)

### 数据质量审查

**v1.0 标准:**
- ✓ 检查缺失值
- ✓ 检查异常值
- ✓ 检查样本数

**v2.0 强化标准:**
- ✓✓ **缺失值 >5% 必须说明处理方法**
- ✓✓ **异常值必须逐个人工核查**
- ✓✓ **样本数必须做功效分析 (power analysis)**
- ✓✓ **数据分布必须检验 (正态性/同方差性)**
- ✓✓ **必须报告数据收集偏倚风险**

**v2.1 实战补充 (Day 2 教训):**
- ✓✓✓ **质量 > 数量** - 194 高质量 > 511 混合
- ✓✓✓ **必须分层分析** - 按数据来源分层
- ✓✓✓ **异常值删除必须说明偏倚** - 删除的样本与保留的样本有系统性差异吗？

**Day 2 案例:**
> 533 样本 → 274 高质量 → 194 无异常值
> 质量提升：51.4% → 70.8% → 100%
> R²变化：0.799 (幻觉) → 0.56 (真实) → 0.58 (验证)

---

### 统计方法审查

**v1.0 标准:**
- ✓ 使用交叉验证
- ✓ 报告 R² 和 MAE

**v2.0 强化标准:**
- ✓✓ **必须使用嵌套交叉验证 (nested CV)**
- ✓✓ **必须报告 95% 置信区间**
- ✓✓ **必须进行多重检验校正**
- ✓✓ **必须检验模型假设 (线性/独立性/同方差)**
- ✓✓ **必须做敏感性分析**
- ✓✓ **必须报告效应量 (effect size)**

---

### 特征工程审查

**v1.0 标准:**
- ✓ 特征有物理意义
- ✓ 报告特征重要性

**v2.0 强化标准:**
- ✓✓ **每个特征必须有文献支持**
- ✓✓ **必须检验多重共线性 (VIF < 5)**
- ✓✓ **必须做特征选择稳定性分析**
- ✓✓ **必须报告特征相关性矩阵**
- ✓✓ **必须排除数据泄露 (data leakage)**

**v2.1 实战补充 (Day 2 教训):**
- ✓✓✓ **VIF 必须全部<5** - 有一个>5 就不合格
- ✓✓✓ **SHAP=0 的特征必须删除** - 无贡献特征增加噪声
- ✓✓✓ **对数特征与原始特征不能共存** - 严重共线性
- ✓✓✓ **特征数/样本数 < 1/10** - 避免过拟合

**Day 2 案例:**
> 14 特征 (全部 VIF>5) → 5 特征 (3 个<5) → 3 特征 (全部<5) ✓
> aspect_ratio SHAP=0 → 删除 ✓
> log_diameter VIF=19.4 → 删除 ✓
> 最终：diameter_nm, length_um, layers (VIF max=3.71) ✓

---

### 模型验证审查

**v1.0 标准:**
- ✓ 使用 5-Fold CV
- ✓ 有测试集

**v2.0 强化标准:**
- ✓✓ **必须使用 3 层嵌套 CV (防止过拟合)**
- ✓✓ **测试集必须完全独立 (外部验证)**
- ✓✓ **必须报告学习曲线**
- ✓✓ **必须做校准曲线 (calibration)**
- ✓✓ **必须与 baseline 模型对比**
- ✓✓ **必须检验模型稳定性 (bootstrap)**

**v2.1 实战补充 (Day 2 教训):**
- ✓✓✓ **嵌套 CV R²必须报告 95% CI** - 点估计无意义
- ✓✓✓ **Bootstrap 必须用 train/test 分割** - 不能在训练集上评估
- ✓✓✓ **学习曲线 Val R²为负说明过拟合** - 需要更多数据或简化模型
- ✓✓✓ **功效分析必须≥0.8** - 否则样本量不足
- ✓✓✓ **baseline 必须正确计算** - 均值预测 R²应该是 0

**Day 2 案例:**
> Nested CV: 0.64 (无 CI) → 0.62 (95% CI: [0.48, 0.72]) ✓
> Bootstrap: 0.00 (错误实现) → -0.03 (正确，小样本不稳定) ✓
> Power: API 错误 → 手动计算 Power=1.0 ✓

## 💬 批判话术 (强化版)

### 数据质量批判

**v1.0:**
> "缺失值 30%，这个比例太高了吧？"

**v2.0 (强化):**
> "缺失值 30.3%，远超 5% 可接受标准。请说明：
> 1. 缺失机制是什么？(MCAR/MAR/MNAR)
> 2. 为什么用中位数填充而不是多重插补？
> 3. 填充引入的偏倚如何量化？
> 4. 敏感性分析做了吗？
> 
> **如果无法回答，这些数据不能用。**"

---

### 统计方法批判

**v1.0:**
> "R²=0.64，还可以吧。"

**v2.0 (强化):**
> "R²=0.64，但：
> 1. 95% 置信区间是多少？
> 2. 嵌套 CV 做了吗？还是普通 CV？
> 3. 有没有数据泄露？
> 4. 基线模型 (如均值预测) 的 R² 是多少？
> 5. 效应量 (Cohen's f²) 是多少？
> 
> **如果连置信区间都没有，这个 R² 毫无意义。**"

---

### 特征工程批判

**v1.0:**
> "特征看起来合理。"

**v2.0 (强化):**
> "14 个特征，请问：
> 1. 每个特征的文献依据是什么？
> 2. VIF 检验做了吗？共线性如何？
> 3. 特征选择稳定性如何？(bootstrap 检验)
> 4. 有没有数据泄露？(如用到了测试集信息)
> 5. 特征相关性矩阵在哪里？
> 
> **没有 VIF 检验的特征工程就是瞎凑。**"

---

### 模型验证批判

**v1.0:**
> "5-Fold CV 够了。"

**v2.0 (强化):**
> "5-Fold CV？请问：
> 1. 为什么不是 10-Fold 或 LOOCV？
> 2. 嵌套 CV 做了吗？(防止模型选择过拟合)
> 3. 外部验证集在哪里？
> 4. 学习曲线显示收敛了吗？
> 5. Bootstrap 稳定性检验做了吗？
> 
> **没有外部验证的模型就是自嗨。**"

---

### 结果解释批判

**v1.0:**
> "length_um 最重要，合理。"

**v2.0 (强化):**
> "length_um 重要性 27%，请问：
> 1. 95% 置信区间是多少？
> 2. SHAP 值做了吗？(全局 + 局部)
> 3. 有没有混杂因素？(如长度与直径相关)
> 4. 因果关系还是相关关系？
> 5. 与文献报道一致吗？
> 
> **没有 SHAP 和置信区间的重要性就是拍脑袋。**"

---

### 可复现性批判

**v1.0:**
> "代码保存了，好。"

**v2.0 (强化):**
> "代码保存了，但：
> 1. GitHub 仓库链接呢？
> 2. requirements.txt 呢？
> 3. 随机种子设置了吗？
> 4. 原始数据能获取吗？
> 5. 第三方能复现吗？
> 
> **没有 GitHub 仓库和随机种子的研究不可信。**"

## 🔬 批判流程 (强化版)

### 阶段 1: 预审查 (5 分钟)

```
□ 检查数据完整性
□ 检查样本量合理性
□ 检查缺失值比例
□ 检查异常值处理
□ 检查数据分布
```

**任何一项不合格 → 直接打回重做**

---

### 阶段 2: 方法审查 (10 分钟)

```
□ 统计方法是否恰当
□ 交叉验证是否严谨
□ 特征选择是否有据
□ 模型假设是否检验
□ 数据泄露是否排除
```

**任何一项有问题 → 要求补充实验**

---

### 阶段 3: 结果审查 (10 分钟)

```
□ R² 置信区间
□ 特征重要性稳定性
□ 与 baseline 对比
□ 敏感性分析
□ 外部验证
```

**任何一项缺失 → 结果不可信**

---

### 阶段 4: 解释审查 (5 分钟)

```
□ 统计显著性 (p 值)
□ 效应量大小
□ 因果推断谨慎性
□ 文献对比
□ 局限性讨论
```

**任何一项过度解读 → 严厉批评**

---

### 阶段 5: 可复现性审查 (5 分钟)

```
□ 代码仓库
□ 环境配置
□ 随机种子
□ 原始数据
□ 方法描述
```

**任何一项缺失 → 拒绝接受**
