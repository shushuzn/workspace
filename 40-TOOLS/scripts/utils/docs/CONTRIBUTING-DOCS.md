# 文档更新指南

**版本:** v1.0  
**创建日期:** 2026-03-12  
**适用范围:** 所有 `README.md` 文档

---

## 📋 何时更新文档

### 必须更新文档的情况

| 触发条件 | 更新内容 | 时限 |
|----------|----------|------|
| 新增功能 | 功能特性、使用示例、API 参考 | 同步发布 |
| 修改参数 | 配置参数表格、示例代码 | 同步发布 |
| 修复 Bug | 更新 FAQ、错误处理说明 | 同步发布 |
| 性能优化 | 更新性能基准数据 | 同步发布 |
| 破坏性变更 | 更新迁移指南、版本说明 | 提前 1 周通知 |

### 可选更新文档的情况

- 代码重构 (功能不变)
- 内部优化 (用户无感知)
- 测试覆盖率提升

---

## 🔧 文档更新流程

### 步骤 1: 确定更新范围

```markdown
更新类型：
- [ ] 新增功能
- [ ] 修改现有功能
- [ ] 修复错误
- [ ] 性能优化
- [ ] 其他：____

影响章节：
- [ ] 快速开始
- [ ] 功能特性
- [ ] 使用示例
- [ ] 配置参数
- [ ] API 参考
- [ ] FAQ
- [ ] 其他：____
```

---

### 步骤 2: 更新文档内容

**原则:**
1. **准确性:** 确保文档与代码一致
2. **完整性:** 覆盖所有变更点
3. **清晰性:** 使用简洁明确的语言
4. **一致性:** 遵循模板格式

**检查清单:**
- [ ] 更新版本号 (vX.Y.Z)
- [ ] 更新最后更新日期
- [ ] 更新功能特性列表
- [ ] 更新配置参数表格
- [ ] 更新示例代码 (如适用)
- [ ] 更新 API 参考 (如适用)
- [ ] 添加/更新 FAQ (如适用)
- [ ] 更新更新日志

---

### 步骤 3: 验证文档

**自动化检查:**
```bash
# 检查 Markdown 语法
markdownlint README.md

# 检查链接有效性
lychee README.md

# 检查拼写错误
codespell README.md
```

**人工检查:**
- [ ] 示例代码可运行
- [ ] 截图清晰 (如适用)
- [ ] 链接无断链
- [ ] 格式统一
- [ ] 术语一致

---

### 步骤 4: 提交文档

**Git 提交规范:**
```bash
# 格式：docs(模块): 简短描述

# 示例:
docs(webui): 添加安全说明章节
docs(graph): 更新性能基准数据
docs(multimodal): 添加单元测试说明
```

**提交内容:**
- [ ] README.md 更新
- [ ] 相关示例代码更新
- [ ] 测试报告更新 (如适用)
- [ ] 更新日志记录

---

### 步骤 5: 发布通知

**变更通知:**
- 小更新 (拼写/格式): 无需通知
- 中等更新 (示例/FAQ): GitHub Release Notes
- 重大更新 (功能/参数): 邮件通知 + Release Notes

---

## 📝 版本命名规范

**格式:** `v主版本。次版本.修订号`

| 变更类型 | 版本号变化 | 示例 |
|----------|------------|------|
| 破坏性变更 | 主版本 +1 | v1.0 → v2.0 |
| 新增功能 (向后兼容) | 次版本 +1 | v1.2 → v1.3 |
| Bug 修复 | 修订号 +1 | v1.2.3 → v1.2.4 |

---

## 📖 更新日志格式

**位置:** README.md 底部的"更新日志"章节

**格式:**
```markdown
### vX.Y.Z (YYYY-MM-DD)

**新增:**
- ✨ 功能 1
- ✨ 功能 2

**改进:**
- 🔧 改进 1
- 🔧 改进 2

**修复:**
- 🐛 修复 1
- 🐛 修复 2

**废弃:**
- ⚠️ 废弃功能 1

**移除:**
- ❌ 移除功能 1
```

**示例:**
```markdown
### v2.5 (2026-03-12)

**新增:**
- ✨ Web UI 界面
- ✨ API 配额监控
- ✨ 公式 LaTeX 渲染

**改进:**
- 🔧 性能优化 (3x 提速)
- 🔧 错误处理改进

**修复:**
- 🐛 修复大文件处理崩溃
- 🐛 修复 Unicode 编码问题
```

## 🔍 文档质量检查

### 自动检查 (CI/CD)

```yaml
# .github/workflows/docs-check.yml
name: Documentation Check

on: [push, pull_request]

jobs:
  docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Check Markdown links
        uses: gaurav-nelson/github-action-markdown-link-check@v1
      
      - name: Check spelling
        uses: rojopolis/spellcheck-github-actions@v0
      
      - name: Check style
        uses: DavidAnson/markdownlint-cli2-action@v11
```

### 人工检查清单

**每次文档更新必须完成:**

- [ ] 示例代码可运行验证
- [ ] 所有链接有效
- [ ] 截图清晰且最新
- [ ] 格式符合模板
- [ ] 术语前后一致
- [ ] 更新日志已记录
- [ ] 版本号已更新
