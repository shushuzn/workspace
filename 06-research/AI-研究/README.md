## 📝 三类笔记

| 类型 | 用途 | 命名规范 | 触发条件 |
|------|------|----------|----------|
| **P-Note** | 论文深度拆解 | `P-2026-PaperName.md` | 单篇论文分析 |
| **C-Note** | 概念抽象骨架 | `C-ConceptName.md` | 跨论文思想连接 |
| **M-Note** | 方法对比分析 | `M-A vs B vs C.md` | 同一主题≥3 篇 P-Note |

**模板位置:** `templates/` 目录

---

## 🔄 五步研究流程

```
STEP 0 → STEP 1 → STEP 2 → STEP 3 → STEP 4 → STEP 5
问题定义 → 信息收集 → 信息抽取 → 对抗审稿 → 交叉验证 → 抽象升级
```

**核心机制:**
- 反碎片检查：新建前必须检查是否可抽象/合并/升级
- 循环更新：P→C→M→Radar→Evolution Log 闭环

## ⭐ 六维评分量表

| 维度 | 含义 | 评分标准 |
|------|------|----------|
| **Novelty** | 新颖性 | 1=增量改进，5=范式转移 |
| **Leverage** | 影响力 | 1=狭窄应用，5=广泛适用 |
| **Evidence** | 证据强度 | 1=理论推测，5=多源验证 |
| **Cost** | 成本效益 | 1=成本高昂，5=性价比极高 |
| **Moat** | 护城河 | 1=易复制，5=难以超越 |
| **Adoption** | 采用难度 | 1=门槛极高，5=开箱即用 |

## 🚀 快速开始

1. **新增论文分析:** 复制 `templates/P-Note-Template.md` → 按流程填写
2. **抽象概念:** 当发现跨论文的共同思想 → 创建 C-Note
3. **方法对比:** 当同一主题≥3 篇 P-Note → 创建 M-Note
4. **更新 Radar:** 每周审查 `00-Radar/README.md`

---

## 📋 检查清单

### 新建 P-Note 前
- [ ] 是否已有相关 P-Note？
- [ ] 能否合并到现有笔记？
- [ ] 能否抽象为 C-Note？

### 新建 C-Note 前
- [ ] 是否有≥2 篇 P-Note 支持？
- [ ] 概念是否足够通用？
- [ ] 是否与现有 C-Note 重复？

### 新建 M-Note 前
- [ ] 是否有≥3 篇 P-Note？
- [ ] 对比维度是否清晰？
- [ ] 是否有统一评估基准？
