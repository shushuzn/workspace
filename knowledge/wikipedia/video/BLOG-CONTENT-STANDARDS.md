# 顶流科普视频文案规范

> 版本：v1.0 | 更新日期：2026-04-07
> 参照：3Blue1Brown / Veritasium / Robert Miles / 李永乐

---

## 一、核心原则

**顶流科普不是"讲清楚"，而是让人体验认知惊喜。**

```
错误思路：把知识掰碎了喂给观众
正确思路：制造认知冲突，让观众自己上瘾
```

---

## 二、开篇钩子（0-15秒）

### 标准结构

```
[一句话反直觉结论] + [为什么这很反直觉]
```

### 示例模板

| 反直觉结论 | 解释为什么反直觉 |
|-----------|-----------------|
| "黑客最喜欢用的一条合法操作，能让整个系统裸奔" | "它本身就是管理员给的权限" |
| "一道小学数学题，难倒了世界上所有计算机" | "但没人知道为什么" |
| "你每天都在用的东西，数学家说它是随机的，但你感觉不是" | "这个矛盾到现在都没解决" |

### 禁止的开篇

- ❌ 背景介绍（"今天我们来讲..."）
- ❌ 定义先行（"首先什么是..."）
- ❌ 设问太长（超过3个设问才抛出答案）

---

## 三、叙事弧线

每个视频必须有清晰的认知阶梯：

```
Step 1: 问题（为什么这个很难）
Step 2: 反直觉发现（等等，实际上是这样的）
Step 3: 证明/原理（为什么这一定成立）
Step 4: 应用/实验（所以我们能做什么）
Step 5: 新问题/局限（但这又引出了什么）
```

每两个 Step 之间必须有"认知障碍清除"：
```
"等等——这不对吧？" → 观众产生疑惑
"其实，..." → 清除障碍
"这意味着——" → 引出下一个阶梯
```

### 段落节奏

每个段落不超过 30 秒（~75 字口语）。超过则拆成两个段落，中间插入：
- 过渡句："好，继续。"
- 悬念："但这还不是最离谱的。"
- 设问："你有没有想过——"

---

## 四、口语化规则

### 语速密度

- 平均句长：**12-18 字**（不是 25）
- 逗号密度：**0.8-1.2 个/句**
- 每 3-4 句话插入一个短句（感叹、反问、重复关键词）

### 词汇替换表

| 学术腔 | 口语替换 |
|--------|---------|
| 因此、所以 | 也就是说、这意味着 |
| 然而 | 不过、但问题来了 |
| 本文/本论文 | 科学家们、研究者 |
| 定义 | 说白了就是、可以理解成 |
| 证明 | 算出来是这样、严格来说 |
| 综上所述 | 总之、最关键的是 |
| 然而 | 不过、但是 |

### 允许的学术词汇

以下词汇在科普语境下是自然的，不需要替换：
- "实验结果"、"证明" — 描述研究过程
- "定义" — "我们可以这样定义它"（而非"定义如下"）
- "本质" — 口语化表达"说白了"

## 五、认知惊喜设计

### 反直觉公式

```
[常识] → [但实际上] → [更深层的道理]
```

### 示例

```
常识：你以为攻击者要找漏洞
但实际上：攻击者用的每一步都是系统允许的
更深层：系统的拓扑结构本身就在泄露信息
```

### 每个段落必须有的元素

1. **悬念钩子**（段首）
2. **认知冲突**（段中）
3. **清除障碍**（段中）
4. **指向下一段**（段尾）

---

## 六、结尾设计

### 禁止的结尾

- ❌ 总结式（"今天我们学了..."）
- ❌ 说教式（"这就是XXX的意义"）
- ❌ 开放式（"以上就是全部内容"）

### 正确的结尾

把问题抛给观众，让他们自己继续想：

```
"所以，如果你是云安全工程师，面对这种攻击，
你会怎么分配权限？是集中管理更安全，还是分散风险？

这个问题，研究者还在探索。
你呢？"

或者：
"你有没有想过——在你每天用的系统里，
还有哪些你习以为常的东西，其实藏着反直觉的结构？

欢迎在评论区聊聊。"
```

### 升华公式

```
具体结论 → 指向更大的图景 → 留白让观众自己感悟
```

好的升华不是"这很重要"，而是：
```
"一个19世纪的数学家发明的工具，
今天可以用来发现云里的攻击者。
数学不解释世界，数学就是世界的一部分。"
```

## 七、配图标注规范

每个 `[画面：]` 必须是：

1. **动态的** — 不是"示意图"，而是"思维导图"
2. **叙事同步的** — 画面帮助观众建立直觉，不只是装饰
3. **视觉类比的** — 把抽象概念用具体图形呈现

### 配图类型优先级

| 优先级 | 类型 | 示例 |
|--------|------|------|
| 1 | 认知冲突可视化 | 迷宫/地图上的攻击路径 vs 拓扑结构图 |
| 2 | 类比可视化 | 编织动作 vs 辫群矩阵变换 |
| 3 | 数据可视化 | LE 指数高低 vs 系统危险程度热力图 |
| 4 | 装饰性 | 论文截图、公式展示 |

## 八、质量检查清单

写完文案后，逐项检查：

- [ ] **开篇 3 秒**：一句话反直觉结论 vs 为什么反直觉
- [ ] **Hook 数量**：每个段落有认知冲突吗？
- [ ] **节奏**：有短句、感叹、悬念吗？（不是均匀语速）
- [ ] **词汇**：无"因此/然而/综上所述/本文/本论文"
- [ ] **句长**：平均 12-18 字，不是 25+ 字
- [ ] **段落**：每段不超过 30 秒
- [ ] **结尾**：问题抛给观众，不是总结
- [ ] **配图**：每个 `[画面：]` 是认知辅助，不是装饰
- [ ] **升华**：指向更大的世界观，不是"很有意义"

## 九、参考案例分析

### 3Blue1Brown 的结构

```
开篇：一个反直觉的几何事实
↓ 每段：为什么直觉是错的
↓ 每段：更深层的结构是什么
↓ 结尾：这个问题打开了什么新世界
```

关键：永远不说"这很重要"，而是让观众自己感受到重要性。

### Robert Miles 的结构

```
开篇：一个具体的安全事故/反直觉发现
↓ 立刻解释原理（30秒内）
↓ 延伸：为什么这不只是个例
↓ 结尾：作为从业者/普通人应该怎么做
```

关键：每段都在回答"所以呢"。

### 李永乐的风格

```
开篇：一个生活中的问题（常见但反直觉）
↓ 从问题出发推导公式/原理
↓ 每步都让观众跟得上
↓ 结尾：回头看开篇的问题，理解更深了
```

关键：设问多、节奏感强、每个问题立刻回答。

## 十、数学符号处理

所有 Unicode 数学符号在送入 TTS 前必须替换：

| 原符号 | TTS 替换 |
|--------|---------|
| σ₁ σ₂ | sigma 1, sigma 2 |
| λ | lambda |
| → | 变成 |
| ∈ | 属于 |
| ∑ | 求和 |
| ∫ | 积分 |
| ≠ | 不等于 |
| ≤ ≥ | 小于等于，大于等于 |
| ∞ | 无穷 |
| ₀ ₁ ₂ | 下标0，下标1，下标2 |
| α β γ | alpha, beta, gamma |
| π | pi |
| Δ | delta |
