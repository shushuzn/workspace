## 🛠️ 核心功能

### 1. 超时检测

**功能:** 监控步骤执行时间，超过阈值自动告警

**配置:**
```json
{
  "timeout_threshold": 300  // 5 分钟
}
```

**使用:**
```bash
py workflow_anomaly_detector.py --check-timeout
```

**输出:**
```
✅ 正常 120.5s / 300s
或
🚨 超时！350.2s > 300s
```

**场景:**
- 工具执行时间过长
- 网络请求超时
- 死循环检测

---

### 2. 自动重试

**功能:** 失败任务自动重试，支持指数退避

**配置:**
```json
{
  "max_retries": 3,
  "retry_delay": 10,
  "exponential_backoff": true
}
```

**重试策略:**
- 第 1 次重试：延迟 10 秒
- 第 2 次重试：延迟 20 秒
- 第 3 次重试：延迟 40 秒

**使用:**
```bash
py workflow_anomaly_detector.py --retry-failed
```

**输出:**
```
⚠️  Step 6 执行失败，1/3 次重试
   延迟：10 秒

✅ 已启动自动重试
```

**场景:**
- 临时网络故障
- 资源暂时不可用
- 偶发性错误

---

### 3. 异常类型识别

**功能:** 自动识别 5 种异常类型

**异常类型:**
| 类型 | 标识 | 触发条件 |
|------|------|----------|
| 超时 | `timeout` | 执行时间超过阈值 |
| 执行错误 | `execution` | 代码执行失败 |
| 验证错误 | `validation` | 数据验证失败 |
| 资源错误 | `resource` | 内存/磁盘不足 |
| 网络错误 | `network` | 网络连接失败 |

**识别逻辑:**
```python
def identify_anomaly_type(error_msg):
    if "timeout" in error_msg:
        return AnomalyType.TIMEOUT
    elif "network" in error_msg:
        return AnomalyType.NETWORK_ERROR
    elif "memory" in error_msg:
        return AnomalyType.RESOURCE_ERROR
    ...
```

---

### 4. 智能降级策略

**功能:** 根据异常类型自动选择降级策略

**降级策略表:**
| 异常类型 | 降级策略 | 说明 |
|---------|---------|------|
| 超时 | 跳过非关键步骤 | 继续执行后续步骤 |
| 网络错误 | 使用缓存数据 | 稍后重试网络请求 |
| 资源错误 | 降低资源需求 | 简化执行流程 |
| 验证错误 | 放宽验证标准 | 记录警告继续 |
| 执行错误 | 无 | 需要人工干预 |

**使用:**
```python
if anomaly_type == AnomalyType.TIMEOUT:
    # 策略：跳过非关键步骤，继续执行
    return True
```
