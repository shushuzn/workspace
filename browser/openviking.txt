      - heading "Challenges in Agent Development" [ref=e252] [level=3]
      - 'link "Permalink: Challenges in Agent Development"':
        - /url: "#challenges-in-agent-development"
      - paragraph: "In the AI era, data is abundant, but high-quality context is hard to come by. When building AI Agents, developers often face these challenges:"
      - list:
        - listitem:
          - strong: Fragmented Context
          - text: ": Memories are in code, resources are in vector databases, and skills are scattered, making them difficult to manage uniformly."
        - listitem:
          - strong: Surging Context Demand
          - text: ": An Agent's long-running tasks produce context at every execution. Simple truncation or compression leads to information loss."
        - listitem:
          - strong: Poor Retrieval Effectiveness
          - text: ": Traditional RAG uses flat storage, lacking a global view and making it difficult to understand the full context of information."
        - listitem:
          - strong: Unobservable Context
          - text: ": The implicit retrieval chain of traditional RAG is like a black box, making it hard to debug when errors occur."
        - listitem:
          - strong: Limited Memory Iteration
          - text: ": Current memory is just a record of user interactions, lacking Agent-related task memory."
      - heading "The OpenViking Solution" [ref=e253] [level=3]
      - 'link "Permalink: The OpenViking Solution"':
        - /url: "#the-openviking-solution"
      - paragraph:
        - strong: OpenViking
        - text: is an open-source
        - strong: Context Database
        - text: designed specifically for AI Agents.
      - paragraph:
        - text: We aim to define a minimalist context interaction paradigm for Agents, allowing developers to completely say goodbye to the hassle of context management. OpenViking abandons the fragmented vector storage model of traditional RAG and innovatively adopts a
        - strong: "\"file system paradigm\""
        - text: to unify the structured organization of memories, resources, and skills needed by Agents.
      - paragraph: "With OpenViking, developers can build an Agent's brain just like managing local files:"
      - list:
        - listitem:
          - strong: Filesystem Management Paradigm
          - text: →
          - strong: Solves Fragmentation
          - text: ": Unified context management of memories, resources, and skills based on a filesystem paradigm."
        - listitem:
          - strong: Tiered Context Loading
          - text: →
          - strong: Reduces Token Consumption
          - text: ": L0/L1/L2 three-tier structure, loaded on demand, significantly saving costs."
        - listitem:
          - strong: Directory Recursive Retrieval
          - text: →
          - strong: Improves Retrieval Effect
          - text: ": Supports native filesystem retrieval methods, combining directory positioning with semantic search to achieve recursive and precise context acquisition."
        - listitem:
          - strong: Visualized Retrieval Trajectory
          - text: →
          - strong: Observable Context
          - text: ": Supports visualization of directory retrieval trajectories, allowing users to clearly observe the root cause of issues and guide retrieval logic optimization."
        - listitem:
          - strong: Automatic Session Management
          - text: →
          - strong: Context Self-Iteration
          - text: ": Automatically compresses content, resource references, tool calls, etc., in conversations, extracting long-term memory, making the Agent smarter with use."

      - heading "1. Filesystem Management Paradigm → Solves Fragmentation" [ref=e321] [level=3]
      - 'link "Permalink: 1. Filesystem Management Paradigm → Solves Fragmentation"':
        - /url: "#1-filesystem-management-paradigm--solves-fragmentation"
      - paragraph:
        - text: We no longer view context as flat text slices but unify them into an abstract virtual filesystem. Whether it's memories, resources, or capabilities, they are mapped to virtual directories under the
        - code: viking://
        - text: protocol, each with a unique URI.
      - paragraph:
        - text: This paradigm gives Agents unprecedented context manipulation capabilities, enabling them to locate, browse, and manipulate information precisely and deterministically through standard commands like
        - code: ls
        - text: and
        - code: find
        - text: ", just like a developer. This transforms context management from vague semantic matching into intuitive, traceable \"file operations\". Learn more:"
        - link "Viking URI" [ref=e322]:

      - heading "3. Directory Recursive Retrieval → Improves Retrieval Effect" [ref=e328] [level=3]
      - 'link "Permalink: 3. Directory Recursive Retrieval → Improves Retrieval Effect"':
        - /url: "#3-directory-recursive-retrieval--improves-retrieval-effect"
      - paragraph:
        - text: Single vector retrieval struggles with complex query intents. OpenViking has designed an innovative
        - strong: Directory Recursive Retrieval Strategy
        - text: "that deeply integrates multiple retrieval methods:"
      - list:
        - listitem:
          - strong: Intent Analysis
          - text: ": Generate multiple retrieval conditions through intent analysis."
        - listitem:
          - strong: Initial Positioning
          - text: ": Use vector retrieval to quickly locate the high-score directory where the initial slice is located."
        - listitem:
          - strong: Refined Exploration
          - text: ": Perform a secondary retrieval within that directory and update high-score results to the candidate set."
        - listitem:
          - strong: Recursive Drill-down
          - text: ": If subdirectories exist, recursively repeat the secondary retrieval steps layer by layer."
        - listitem:
          - strong: Result Aggregation
          - text: ": Finally, obtain the most relevant context to return."
      - paragraph:
        - text: "This \"lock high-score directory first, then refine content exploration\" strategy not only finds the semantically best-matching fragments but also understands the full context where the information resides, thereby improving the globality and accuracy of retrieval. Learn more:"
