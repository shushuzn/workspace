# 🚨 工作流强制执行规则

**创建日期:** 2026-03-20  
**原则:** 不简化工作流，强化执行机制

---

## 🔴 核心规则

### 规则 1: 每次任务开始必须运行自动加载器
```bash
py 30-scripts-tools\workflow_autoloader.py
```

**效果:** 自动显示完整 20 步工作流，不允许跳过！

---

### 规则 2: 每次回复必须包含工作流执行状态
**模板:**
```markdown
## 主工作流执行状态

**Flow ID:** 20260318-universal-workflow-001
**版本:** 1.3.4
**步骤:** 20 步

### 当前进度
- [x] Step 1: 上下文加载验证
- [x] Step 2: Flow ID 绑定
- [ ] Step 3: 任务解析
...
```

---

### 规则 3: Git 提交前必须 100% 完成
**检查命令:**
```bash
py 30-scripts-tools\workflow_autoloader.py --check
```

**阻止条件:** 完成率 <100% → 不允许提交

---

### 规则 4: 违反规则的后果
| 违规 | 后果 |
|------|------|
| 未运行自动加载器 | 任务暂停，重新执行 |
| 未显示执行状态 | 回复无效，重新回复 |
| 未完成就提交 | Git Hook 阻止 |

## 🛡️ 强制机制

### 机制 1: 自动加载器
**文件:** `workflow_autoloader.py`  
**作用:** 每次任务开始自动显示 20 步

### 机制 2: 状态跟踪
**文件:** `execution-state.json`  
**作用:** 实时跟踪每步完成状态

### 机制 3: Git Hook
**文件:** `.git/hooks/pre-commit`  
**作用:** 检查完成率 <100% 则阻止提交

### 机制 4: 会话脚本
**文件:** `start-session.bat` / `end-session.bat`  
**作用:** 会话开始/结束强制检查

## ⚠️ 重要提醒

**不简化！不跳过！不依赖记忆！**

每次任务开始：
1. 运行 `workflow_autoloader.py`
2. 复制执行记录模板
3. 逐步打勾

每次任务结束：
1. 检查 20 步全部完成
2. 运行完成度检查
3. Git 提交

---

**目标:** 让工作流执行成为系统强制，而不是记忆依赖！
