## 🛡️ 5 层防护体系

```
┌─────────────────────────────────────────────────────────┐
│  Layer 1: 工作流加载器 (前置强制)                        │
│  - 任务开始前必须读取 workflow.json                      │
│  - 生成步骤检查清单                                      │
│  - 不读取 → 阻断任务执行                                 │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│  Layer 2: 步骤追踪器 (执行中监控)                        │
│  - 每步执行前验证顺序                                    │
│  - 记录到 checkpoint.json                                │
│  - 跳步 → 阻断并报警                                     │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│  Layer 3: 工具执行器约束 (工具层防护)                    │
│  - tool_executor.py 检查当前步骤                         │
│  - 只允许执行当前步骤的工具                              │
│  - 非当前步骤 → 拒绝执行                                 │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│  Layer 4: 完成验证器 (后置强制)                          │
│  - 验证 12 步全部完成                                     │
│  - 验证执行日志完整                                      │
│  - 有缺失 → 禁止提交 Git                                 │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│  Layer 5: Git 提交钩子 (最后防线)                        │
│  - pre-commit hook 检查工作流合规性                      │
│  - 未通过 → 提交失败                                     │
│  - 通过后才能 push                                       │
└─────────────────────────────────────────────────────────┘
```

## 🚀 使用方法

### 1. 开始工作流

```bash
# 启动工作流 (必须第一步执行)
py 30-scripts-tools\workflow_enforcer.py --start

# 输出:
# [OK] 工作流已启动：20260318-universal-workflow-001
# [ENFORCEMENT] 强制模式已启用
```

### 2. 按顺序执行步骤

```bash
# 检查步骤 1 是否可执行
py 30-scripts-tools\workflow_enforcer.py --check-step 1

# 执行步骤 1 的任务...
# (你的实际任务执行)

# 标记步骤 1 完成
py 30-scripts-tools\workflow_enforcer.py --complete-step 1

# 尝试跳步到步骤 5 (会被阻断!)
py 30-scripts-tools\workflow_enforcer.py --check-step 5
# [BLOCKER] 步骤跳跃检测!
# 操作被阻断 - 请按顺序执行步骤
```

### 3. 查看状态

```bash
py 30-scripts-tools\workflow_enforcer.py --status

# 输出:
# Flow ID: 20260318-universal-workflow-001
# 状态：in_progress
# 当前步骤：2/12
# 已完成：[1]
# 违规次数：1
```

### 4. 验证完成

```bash
# 验证 12 步是否全部完成
py 30-scripts-tools\workflow_enforcer.py --validate

# 如果未完成:
# [BLOCKER] 工作流未完成!
# 缺失步骤：[2, 3, 4, ...]
# Git 提交被阻断

# 如果完成:
# [OK] 工作流验证通过 - 12/12 步骤完成
```

### 5. Git 提交

```bash
# 检查工作流是否可提交
py 30-scripts-tools\workflow_enforcer.py --can-commit

# 如果通过，正常提交
git add .
git commit -m "任务完成"
git push

# Git hook 会自动检查工作流合规性
# 未通过 → 提交失败
```

## 📋 12 个核心步骤

| Step | 名称 | 阻塞性 | 说明 |
|------|------|--------|------|
| 1 | 上下文加载验证 | ✅ | 验证 7 个核心文件 (<100KB) |
| 2 | Flow ID 绑定 | ✅ | 创建或绑定 Flow ID |
| 3 | 任务解析 | ✅ | 分析任务类型和复杂度 |
| 4 | 工具/工作流选择 | ✅ | 选择合适的工具或子工作流 |
| 5 | 子工作流调度 | ✅ | 调用子工作流执行 |
| 6 | 工具执行 | ✅ | 执行选定的工具 |
| 7 | 执行日志记录 | ❌ | 记录到 execution-log.json |
| 8 | 检查点保存 | ❌ | 保存到 checkpoint.json |
| 9 | 批判者最终审查 | ✅ | Auto-Critic v7.0 (≥95 分) |
| 10 | 质量门禁 | ✅ | 质量检查 (≥80 分) |
| 11 | 会话压缩保存 | ✅ | 压缩到 daily note |
| 12 | Git 提交推送 | ✅ | 提交并推送 |

**阻塞性步骤 (✅):** 必须完成才能继续  
**非阻塞性步骤 (❌):** 建议完成，可跳过

## ⚠️ 违规处理

### 跳步检测

```
[BLOCKER] 步骤跳跃检测!
     当前步骤：1
     尝试执行：5
     操作被阻断 - 请按顺序执行步骤
```

**处理:** 从当前步骤开始按顺序执行

### 未完成阻断

```
[BLOCKER] 工作流未完成!
     缺失步骤：[2, 3, 4, ...]
     Git 提交被阻断
```

**处理:** 补全缺失步骤后重新验证

### Git Hook 阻断

```
[Git Hook] 工作流检查：8/12 步骤，状态：in_progress
[BLOCKER] 工作流未完成！提交被阻断
```

**处理:** 完成所有步骤并通过验证

**位置:** `30-scripts-tools/tools_registry.json`

**命令:**
```bash
py 30-scripts-tools\workflow_enforcer.py [选项]
```

**选项:**
- `--start` - 启动工作流
- `--check-step <N>` - 检查步骤 N 是否可执行
- `--complete-step <N>` - 标记步骤 N 完成
- `--validate` - 验证工作流完成
- `--can-commit` - 检查是否可 Git 提交
- `--status` - 查看当前状态
- `--flow-id <ID>` - 指定 Flow ID (默认：20260318-universal-workflow-001)
