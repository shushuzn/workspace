## Research: MetaClaw (arXiv:2603.17187)
**Time:** 2026-03-23T18:40:00
**Paper:** MetaClaw: Just Talk -- An Agent That Meta-Lears and Evolves in the Wild
**URL:** https://arxiv.org/abs/2603.17187

### Core Problem
LLM agents deployed in the wild remain static, failing to adapt as user needs evolve. OpenClaw handles 20+ channels with diverse, evolving workloads.

### Solution: Dual Mechanism
| Mechanism | Timescale | Update Type | Downtime |
|-----------|-----------|-------------|----------|
| Skill-driven fast adaptation | Seconds | Gradient-free (LLM evolver) | Zero |
| Opportunistic policy optimization | Minutes-hours | Gradient-based (Cloud LoRA + RL-PRM) | User-inactive windows |

### Key Components
1. **Skill Evolver (ℰ)** — LLM analyzes failure trajectories → synthesizes behavioral instructions
2. **Skill Library (𝒮)** — Dual role: meta-parameter + adaptation basis
3. **OMLS (Opportunistic Meta-Learning Scheduler)** — Monitors sleep/inactivity/calendar → triggers training
4. **Skill Generation Versioning** — Separates support data from query data to prevent reward contamination

### Algorithm Summary
```
For each task τ_i:
  1. Serve with current meta-model (θ, 𝒮_g)
  2. Collect trajectory ξ_i
  3. If failure → add to support set 𝐷_sup
  4. If success → add to RL buffer ℬ with generation stamp
  5. If |𝐷_sup| ≥ threshold:
     - Evolve skills: 𝒮_{g+1} = 𝒮_g ∪ ℰ(𝒮_g, 𝐷_sup)
     - Flush stale samples from ℬ
     - Increment g
  6. If OMLS detects idle AND |ℬ| ≥ batch_size:
     - RL update via cloud LoRA
     - Hot-swap weights
```
